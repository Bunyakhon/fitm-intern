FITM-INTERN

นโยบายความเป็นส่วนตัว

ปรับปรุงร่าง: 16 ตุลาคม 2569 · วันที่มีผลใช้บังคับ: รออนุมัติ

ร่างสำหรับตรวจทาน — ยังไม่ใช่ฉบับประกาศใช้

ผู้รับผิดชอบโครงการต้องยืนยันผู้ให้บริการ/ผู้ควบคุมข้อมูล ช่องทางติดต่อ และอนุมัติเนื้อหาก่อนประกาศใช้ เอกสารนี้อธิบายการทำงานที่ตรวจพบในระบบ ไม่ใช่การรับรองการปฏิบัติตามกฎหมายครบทุกประการ

1. ขอบเขตและประเภทข้อมูล

ร่างนี้อธิบายข้อมูลที่ระบบรองรับตามโมดูลและกิจกรรมที่ใช้งาน ไม่ได้หมายความว่าผู้ใช้ทุกคนต้องให้ข้อมูลทุกรายการ ข้อมูลอาจมาจากผู้ใช้ ผู้เกี่ยวข้องตามขั้นตอนงาน เอกสารนำเข้า หรือ Google เมื่อเลือกใช้บริการดังกล่าว

รอยืนยันก่อนประกาศใช้: ผู้ควบคุมข้อมูล ผู้ประมวลผลข้อมูล ฐานการประมวลผลของแต่ละกิจกรรม ข้อมูลที่จำเป็น/สมัครใจ และผลหากไม่ให้ข้อมูล การรับทราบหน้านี้ไม่ใช่ความยินยอมแบบครอบคลุม หากกิจกรรมใดต้องใช้ความยินยอมแยก ผู้รับผิดชอบต้องจัดให้มีกระบวนการที่เหมาะสมก่อนดำเนินการ

2. ชื่อ อีเมล รหัสนักศึกษา และบัญชี

ระบบใช้ชื่อ นามสกุล อีเมล รหัสนักศึกษาที่ดึงจากอีเมล และข้อมูลสถานะบัญชี/บทบาท บัญชีแบบรหัสผ่านจัดเก็บค่าแฮชด้วย bcrypt บัญชีที่สร้างผ่าน Google เท่านั้นอาจไม่มีรหัสผ่านในระบบ รายละเอียดสิทธิ์ขึ้นกับบัญชีและข้อมูลหน่วยงานที่ Backend ตรวจสอบ

3. ประวัตินักศึกษาและงานสหกิจศึกษา

ระบบรองรับข้อมูลคณะ ภาควิชา สาขา ชั้นปี ผลการเรียน รูปประจำตัว วันเกิด ที่อยู่ ช่องทางติดต่อ ทักษะ การศึกษา และการฝึกอบรม รวมถึงข้อมูลครอบครัวและผู้ติดต่อฉุกเฉินเมื่อกรอกในประวัติ

ข้อมูลการดำเนินงานรวมถึงคำร้อง การพิจารณา อาจารย์ที่ปรึกษา สถานประกอบการ/สถานที่ปฏิบัติงาน บันทึกการฝึกงาน ข้อเสนอแนะจากผู้ดูแล นัดหมายและผลการนิเทศ กิจกรรม เอกสารประกอบ และประวัติการแก้ไขตามโมดูลที่ใช้งาน

แบบประวัติรองรับข้อมูลศาสนา สุขภาพ โรคประจำตัว การแพ้ และข้อมูลส่วนบุคคลที่ต้องพิจารณาเป็นพิเศษ ผู้ดูแลต้องยืนยันความจำเป็น ฐานการประมวลผล การจำกัดการเข้าถึง และการขอความยินยอมแยกเมื่อจำเป็นก่อนใช้งานจริง การสมัครสมาชิกไม่ใช้แทนกระบวนการนี้

4. Resume และเอกสารอัปโหลด

เอกสารที่รองรับมี Resume ผลการศึกษา สำเนาบัตรประชาชน/บัตรนักศึกษา เอกสารประกอบ และเอกสารโครงงานหรือสมุดบันทึกตามงานที่เกี่ยวข้อง ระบบอาจเก็บชื่อไฟล์ ประเภทไฟล์ ขนาด ค่าแฮช รุ่นของเอกสาร และข้อมูลประวัติ เอกสารอาจมีเลขประจำตัว รูปถ่าย หรือข้อมูลของบุคคลอื่น ผู้ใช้ควรส่งเฉพาะสิ่งที่จำเป็นและมีสิทธิ์ส่ง

เมื่อใช้การนำเข้า PDF ไฟล์จะถูกส่งให้บริการอ่าน PDF/OCR/NLP ของโครงการเพื่อสร้างข้อมูลร่างให้ตรวจทานก่อนยืนยัน ระบบมีการวิเคราะห์ Resume/ข้อมูลตำแหน่งงานเพื่อช่วยจับคู่ด้วย ผลวิเคราะห์อาจคลาดเคลื่อน ไม่ได้เป็นผลรับรองคุณสมบัติ

5. ข้อมูล Google และบริการที่เกี่ยวข้อง

เมื่อเปิดใช้งานและผู้ใช้เลือก Google ระบบใช้ Google Identity Services และตรวจ ID token โดยตรวจผู้ออก ผู้รับ อายุ token และ nonce รวมถึงนโยบายอีเมล/โดเมนที่กำหนด ข้อมูลที่ใช้มีรหัสบัญชี Google (sub) อีเมล สถานะยืนยันอีเมล/โดเมน และชื่อสำหรับการสมัครใหม่ตามขั้นตอนเดิม โดยมีการผูกตัวตนกับบัญชีที่ระบบอนุญาต

ขั้นตอนที่ตรวจพบไม่ได้ขอรหัสผ่าน Google หรือสิทธิ์อ่าน Gmail/Google Drive; Application JWT ของ FITM-INTERN แยกจาก Google ID token การตรวจอีเมลในแบบฟอร์มเว็บไซต์ไม่ได้เทียบเท่าการยืนยันตัวตนโดย Google

บางหน้าอาจโหลดทรัพยากรจาก CDN และงานรับประกาศของสถานประกอบการอาจใช้บริการอีเมลหรือ Cloudflare Turnstile ตามการตั้งค่า ผู้ดูแลต้องยืนยันรายชื่อผู้ให้บริการ เงื่อนไขการประมวลผล ที่ตั้งจัดเก็บ และมาตรการส่งข้อมูลต่างประเทศที่เกี่ยวข้องก่อนประกาศใช้ ไม่ใช้ร่างนี้รับรองนโยบายของบุคคลภายนอก

6. วัตถุประสงค์การใช้ข้อมูล

เพื่อสร้างและยืนยันบัญชี จัดการสิทธิ์ จัดทำประวัติ/เอกสาร ประสานคำร้องและการพิจารณา ค้นหาและจับคู่โอกาสฝึกงาน ติดตามการปฏิบัติงานและนิเทศ และติดต่อประสานงานตามกิจกรรม ผู้รับผิดชอบต้องจับคู่แต่ละวัตถุประสงค์กับฐานการประมวลผลที่เหมาะสมก่อนประกาศใช้

7. การเข้าถึงและเปิดเผยข้อมูล

Backend ตรวจบัญชี บทบาท ความเป็นเจ้าของ และขอบเขตของงานตาม API ที่เกี่ยวข้อง นักศึกษา อาจารย์ ผู้รับผิดชอบภาควิชา และเจ้าหน้าที่เข้าถึงตามสิทธิ์ ส่วนผู้ดูแลในสถานประกอบการใช้ช่องทางและลิงก์ที่จำกัดขอบเขตตามขั้นตอนงาน

ผู้รับผิดชอบต้องยืนยันรายการข้อมูล ผู้รับข้อมูล และความจำเป็นของการเปิดเผยในแต่ละกิจกรรม รวมถึงผู้ให้บริการภายนอกก่อนประกาศใช้ ไม่ควรนำข้อมูลที่เข้าถึงได้ไปใช้หรือเผยแพร่นอกวัตถุประสงค์งาน

8. การรักษาความปลอดภัย

มาตรการที่ตรวจพบรวมถึง bcrypt สำหรับรหัสผ่าน การตรวจ JWT/สิทธิ์ฝั่ง Backend การตรวจ Google token และข้อจำกัดการเข้าถึงไฟล์ส่วนตัว มาตรการเหล่านี้ไม่ได้รับรองว่าข้อมูลทุกประเภทเข้ารหัสไว้ทั้งหมดหรือป้องกันเหตุได้ทุกกรณี

ผู้ใช้ควรรักษาอุปกรณ์และข้อมูลยืนยันตัวตน ผู้ดูแลต้องยืนยันมาตรการใช้งานจริง การสำรองข้อมูล และกระบวนการรับมือเหตุละเมิดก่อนประกาศใช้

9. Session, Cookies และข้อมูลยืนยันตัวตน

เว็บไซต์ใช้ localStorage หรือ sessionStorage เก็บข้อมูล Session/JWT ตามการเลือกจดจำการเข้าสู่ระบบ พร้อมกลไกหมดอายุ ออกจากระบบ และสื่อสารสถานะระหว่างแท็บ Browser แยก Storage ตาม Origin ดังนั้น localhost และ 127.0.0.1 ไม่ได้ใช้ Session ชุดเดียวกัน การออกจากระบบใน Browser ไม่ควรถูกถือว่าเพิกถอน JWT ที่ถูกคัดลอกทุกชุดบน Server โดยอัตโนมัติ

งานส่งลิงก์ยืนยันประกาศซ้ำของสถานประกอบการใช้ Cookie แบบ HttpOnly และ SameSite=Lax โดยเปิด Secure ใน Production และมีอายุ/ขอบเขตตามการตั้งค่า เครื่องมือผู้ดูแล Environment ที่แยกจากเว็บไซต์หลักมี Cookie ยืนยันตัวตนของตนเอง จึงไม่อ้างว่าโครงการไม่มี Cookie ทุกกรณี

10. การจัดเก็บและระยะเวลาเก็บรักษา

ข้อมูลบัญชีและข้อมูลการดำเนินงานจัดเก็บใน PostgreSQL และไฟล์/ข้อมูลประกอบจัดเก็บตามการตั้งค่าของระบบ ยังไม่ยืนยันกำหนดอายุเก็บรักษารายประเภท การสำรองข้อมูล และวิธีลบหรือทำให้ไม่ระบุตัวบุคคล ผู้รับผิดชอบต้องกำหนดและอนุมัติก่อนประกาศใช้

ไม่ควรเข้าใจว่าข้อมูลทั้งหมดถูกลบอัตโนมัติเมื่อออกจากระบบ จบการศึกษา หรือเลิกใช้งาน การเก็บประวัติและสำเนาสำรองต้องพิจารณาแยกจากข้อมูลที่แสดงบนหน้าจอ

11. การแก้ไขข้อมูลและการขอใช้สิทธิ

ผู้ใช้แก้ไขข้อมูลที่ระบบเปิดให้แก้ได้ตามสิทธิ์ สำหรับการขอเข้าถึง สำเนา แก้ไข ลบ จำกัด คัดค้าน โอนย้าย หรือถอนความยินยอมในกรณีที่เกี่ยวข้อง ให้ติดต่อผู้รับผิดชอบตามช่องทางที่จะยืนยันไว้ การพิจารณาขึ้นกับข้อเท็จจริง ฐานการประมวลผล และข้อกำหนดที่ใช้บังคับ ไม่รับรองการลบทุกข้อมูลทันที

รอยืนยัน: วิธีรับคำขอ ตรวจสอบผู้ขอ ระยะเวลาดำเนินการ ช่องทางติดตาม/ร้องเรียน และข้อจำกัดของสิทธิ การแก้ประวัติผ่านหน้าจอไม่เท่ากับการลบประวัติหรือสำเนาสำรองทั้งหมด

12. ผู้ควบคุมข้อมูลและช่องทางติดต่อ

รอผู้ดูแลโครงการยืนยันก่อนประกาศใช้: ชื่อและที่อยู่ผู้ควบคุมข้อมูล หน่วยงาน/เจ้าหน้าที่ที่รับผิดชอบ ช่องทางติดต่อเรื่องข้อมูลส่วนบุคคล และผู้ประสานงานหรือเจ้าหน้าที่คุ้มครองข้อมูลเมื่อเกี่ยวข้อง ร่างนี้ไม่มีอีเมลหรือเบอร์โทรสมมติให้ใช้ส่งข้อมูลส่วนบุคคล

13. การปรับปรุงนโยบาย

ผู้รับผิดชอบต้องตรวจร่างนี้ให้ตรงกับการใช้ข้อมูลจริง อนุมัติฉบับและวันที่มีผล รวมถึงวิธีแจ้งการเปลี่ยนแปลงก่อนประกาศใช้ โดยต้องยืนยันฐานการประมวลผล ข้อมูลอ่อนไหว ผู้รับข้อมูล ระยะเวลาเก็บรักษา และกระบวนการใช้สิทธิที่ระบุว่ารอข้อมูลข้างต้น

หน้า Register ไม่มี Checkbox ยอมรับเงื่อนไขหรือรับทราบนโยบาย และระบบยังไม่บันทึกฉบับ/เวลาการรับทราบย้อนหลัง การสมัครสมาชิกไม่ใช่หลักฐานว่าได้อ่านนโยบายครบทุกข้อหรือความยินยอมแยกสำหรับทุกกิจกรรม ขั้นตอน Google คงเดิม
